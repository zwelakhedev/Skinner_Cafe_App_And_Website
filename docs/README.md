\# Skinner Cafe - Project Documentation



\## Overview



This directory contains project documentation for the Skinner Cafe website, Android application, API, and database.



Documentation should describe the agreed requirements and the actual implementation status. Planned features must be identified as planned until they have been implemented and tested.



\## Directory Structure



\- `requirements/` - Functional requirements, non-functional requirements, user stories, and acceptance criteria.

\- `design/` - Architecture decisions, technical design notes, and data-flow descriptions.

\- `diagrams/` - System architecture, database ERDs, UML, and process diagrams.

\- `wireframes/` - User-interface sketches and approved design references.

\- `testing/` - Test plans, test evidence, and testing summaries.

\- `reports/` - Project progress reports and technical findings.

\- `presentations/` - Presentation materials and demonstrations.



\## Documentation Guidelines



\- Use descriptive filenames.

\- Include dates or version numbers when useful.

\- Keep diagrams consistent with the implemented system.

\- Record important architectural decisions and their rationale.

\- Do not include passwords, tokens, database credentials, or personal customer data.

\- Update documentation when a significant design or implementation decision changes.



\## Architecture Documentation



The intended architecture consists of two client applications communicating with one shared ASP.NET Core Web API, which accesses a SQL Server database.



The website, Android application, API, and database should be documented as separate components with clearly defined responsibilities.



\## Project Status



The repository architecture and initial API project are being established. Detailed requirements, final database design, Android implementation, and backend business features will be developed incrementally.
